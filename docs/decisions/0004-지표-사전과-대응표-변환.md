# 0004-지표 사전, 대응표, 외부 존·코드 체계 변환

- 상태: 제안 (0단계에서 확정)
- 날짜: 2026-10-18
- 관련: PLAN G5, G6, G25, G26, 6.2절 1-5·1-7·1-8, 6.4절 3-3a / DESIGN 4.2

## 배경
대응표 변환은 지표의 성질(합산형·비율형)에 따라 달라야 하는데 DESIGN 4.2에는 그 정보가 없고, `weight`는 방향에 따라 다르다. λ2(변화율)를 위해 2020년 자료를 base_2025 경계로 옮겨야 한다. 외부 OD는 단위 체계가 다르다(KTDB 2023 기준 250존, 인구총조사 통근·통학 2020 250개, 국내인구이동 229개).

## 선택지
변환 근거는 경계 중첩 면적 가중과 행정동 재집계 중에서 고른다. OD는 모든 자료를 base_2025로 나눠 맞추는 방식과 나누지 않는 공통 단위에서 계산하는 방식 중에서 고른다.

## 결정
1. `indicators`(indicator, unit, kind = extensive / intensive, numerator, denominator, description)를 둔다. 비율형은 분자·분모를 옮긴 뒤 다시 계산한다.
2. `region_crosswalk`에 교차 질량(`overlap_area_km2`, `overlap_pop`)을 저장하고, 방향별 가중치는 함수로 유도한다: w(o → n) = m(o∩n) / Σ_n m(o∩n), w(n → o) = m(o∩n) / Σ_o m(o∩n).
3. 변환은 행정동 단위 재집계를 기본으로 한다. 시군구·시도의 구성을 바꾸는 변경(2020 → 2025의 창원 용지동 이관·군위군 편입·부천시 분할, 2026년 시도·시군구 개편 전부. PLAN 6.2절 표의 나머지 세 건은 코드·명칭만 바뀐다)은 행정동을 나누지 않으므로 행정동 인구 합으로 정확히 옮긴다. 행정동이 나뉘는 경우에만 면적·인구 가중을 쓰고, 면적은 base_2025 경계 하나에서 가져온다. 경계 자료는 판마다 면적이 달라 경계 중첩만으로 옮기면 오차가 생긴다.
4. 비교 시점 변환: 2020 행정동 값을 base_2025 시군구로 옮겨 `region_attributes`(ref_date 2020, 경계 base_2025, `derived_via` = 대응표 ID)에 둔다. 시도 합계도 2025 경계로 다시 낸다(군위군: 경북 → 대구). 비교 시점의 선택(2020)은 ADR 0003에서 확정한다.
5. 외부 존·코드 체계: KTDB 존 번호, 인구총조사·국내인구이동 단위를 `region_codes`와 대응표에 넣는다. `code_system`은 기관명이 아니라 체계 이름(행정표준코드, 한국행정구역분류 7자리·8자리, KTDB 존 번호)으로 둔다.
6. OD 변환은 F′ = Wᵀ·F·W다(W: 존 → 지역 배분 행렬, 행 합 1).
   - 합치기만 있으면 총량·행합·열합이 보존되는 정확 변환이다.
   - 나누기가 있어도 행합 = Wᵀ·O, 열합 = Wᵀ·D가 성립하고, 나뉜 지역을 원래 존으로 다시 합치면 원본이 된다. 가정이 들어가는 것은 셀 단위 배분이다. 출발 쪽과 도착 쪽 배분 비율이 서로 독립이라고 가정하는 셈이므로 해당 셀에 `split_assumed`를 남긴다. 나뉘는 존의 내부 통행(대각)도 같은 식으로 새 지역 간·지역 내부 통행에 배분된다. 기본 가중은 인구 비율이며, 이 가정은 `sources`와 `runs`에 기록한다.
   - 여러 존이 한 지역으로 합쳐져 생기는 지역 내부 통행은 통행량 거리(PLAN 3-3a)의 `O_i`, `D_j` 계산에서 빠진다.
   - 나누기가 필요한 경우: KTDB 2023의 부천시(1 → 3), 인구총조사 2020의 부천시와 창원 의창구(2021-07-01 용지동 이관). 국내인구이동 229개는 base_2025의 일반구를 상위 시로 합친 단위라서, base_2025로 옮기려면 시 12개를 일반구 35개로 나눠야 한다.
7. OD 구조 자체를 쓰는 계산(통행량 거리, `δ̄`, 중력 대조군, 입력 간 비교)은 나누지 않는 공통 단위에서 한다. KTDB 2023은 부천시를 합친 250개, 인구총조사 2020은 부천시와 창원 의창구·성산구를 합친 249개, 국내인구이동은 229개다. 인구 비율로 나눈 셀은 같은 상위 단위의 하위 지역들을 거리 구조상 쌍둥이(지역별 상수만 다름)로 만들어 `δ̄`를 트리 쪽으로 미는 편향을 낳기 때문이다. 곡률의 이웃 분포처럼 base_2025 단위가 꼭 필요한 곳에서만 `split_assumed` 셀을 쓴다.

## 영향
- DESIGN.md 수정 절: 4.2 `region_attributes`(`derived_via`), `region_crosswalk`(교차 질량), `links`·`interactions`(`crosswalk_id`, `split_assumed`), `indicators` 신설
- CLAUDE.md 규약: "원 데이터 코드는 `source_code`에만 둔다"는 ADR 0002를 채택할 때 `region_codes`를 포함하도록 고친다
- 코드·데이터: `spatial/crosswalk`(합산형·비율형·OD 변환 함수), `schema`, fixture `crosswalk_split_merge`·`od_crosswalk`

- 나누기 가정(인구 비율)의 민감도. 핵심 결론은 나누지 않는 공통 단위에서도 확인한다
