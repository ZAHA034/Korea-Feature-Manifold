# 0001-문서·저장소 구조

- 상태: 제안 (0단계에서 확정)
- 날짜: 2026-10-20
- 관련: PLAN 2.1, 5.2, G22, G23, 6.1a절 규칙 예외, 문서 머리표의 변경 규칙 / DESIGN 11.2 / CLAUDE.md

## 배경
PLAN 5.2가 DESIGN 11.2에 더할 디렉토리(`core`, `configs/reference` 등)를 정했지만 DESIGN에는 아직 없다. 저장소는 OneDrive 폴더에 있고, PLAN은 v0.3에서 동결해 본문을 고치지 않는다. 0S의 규칙 예외와 PLAN 본문 사실 표의 CSV 이전은 이 ADR로 처리하도록 PLAN이 정해 두었다.

## 선택지
저장소를 OneDrive 밖(`C:\dev\kfm`)으로 옮기기 / 그대로 두고 가상환경과 자료만 밖에 두기(S0에서 정했다). PLAN을 계속 고치기 / 동결하고 ADR로만 바꾸기(PLAN이 정했다).

## 결정
1. 디렉토리: PLAN 5.2의 추가분을 DESIGN 11.2에 옮긴다. `src/kfm/core/`(config, hashing, runs, io, world, seed. G22), `pipeline.py`, `cli.py`, `configs/presets/density/`, `configs/reference/`(G23), `data/derived/run_id=<id>/`, `notebooks/spike/`, `docs/reports/`다. 문서는 `docs/`에 DESIGN.md, PLAN.md(동결), IMPLEMENTATION.md(구현 지시서), `decisions/`, `reports/`를 두고, 루트에 CLAUDE.md, README.md, NOTICE.md(자료 출처와 ODbL 고지)를 둔다.
2. 위치(PLAN 2.1): 저장소는 OneDrive 폴더에 그대로 둔다. 가상환경은 `C:\dev\kfm-venv`(`UV_PROJECT_ENVIRONMENT`)에, 자료는 `C:\dev\kfm-data`에 두고, 코드는 환경 변수 `KFM_DATA_DIR`로 자료 위치를 받는다(없으면 저장소의 `data/`). 다른 기기에서는 이 폴더를 열지 않고 GitHub에서 새로 받는다(`.git` 손상 위험).
3. PLAN 동결 규칙: PLAN 본문은 고치지 않는다. 계획이 바뀌면 ADR을 쓰고, 채택한 ADR이 대체하는 PLAN 절은 ADR의 "영향"에 적는다. PLAN 변경 이력에는 `ADR NNNN | 상태와 날짜 | 요약` 한 행만 더한다. DESIGN.md는 ADR이 채택된 뒤에만 고치고, 규약을 바꾸는 ADR은 CLAUDE.md도 같은 커밋에서 고친다(PLAN 11.1).
4. ADR 운영: 번호는 한 번 배정하면 바꾸거나 다시 쓰지 않고, 파일명은 `NNNN-한글-제목.md`다. 상태는 제안 → 채택 → 대체됨(→ NNNN)이다. 채택한 항을 바꿀 때는 새 ADR로 대체하거나, 상태 줄에 날짜·시각과 고친 항을 적어 개정한다(0010, 0013의 선례).
5. 0S 규칙 예외(PLAN 6.1a): `notebooks/spike/`의 코드는 `kfm` 패키지, `runs` 기록, 스키마 검증, 테스트 규칙 밖이다. 재현성은 요구하지 않고 노트북 첫 셀에 자료 파일명·날짜·해시, 패키지 목록, 가정값을 적는다. 결과는 결정의 근거로만 쓰고 결과물로 인용하지 않는다.
   - 예외는 이 네 규칙에만 적용한다. `data/raw/` 불변, 좌표계·단위 규약, 거리 행렬의 비대칭 보존은 0S에도 적용한다.
   - 0S 코드는 `kfm`으로 가져오지 않는다. 재사용하려면 CLAUDE.md 규칙대로 fixture 테스트부터 다시 쓴다. 다만 지우지는 않는다. NOTICE.md가 이 코드를 ODbL 4.6의 "만든 방법"으로 가리키기 때문이다.
   - 0S 외의 탐색 실험은 이 예외에 들지 않으며, 필요하면 그 실험의 ADR이 정한다.
6. 참조 사실 표의 `configs/reference/` 이전(PLAN 변경 규칙): PLAN 본문의 사실 표인 행정구역 변경 목록과 코드(6.2절), 제공처 주소(8장), 공표 합계값(6.2·6.3절 완료 기준)은 1단계에서 `configs/reference/` CSV로 옮긴다. 옮긴 뒤에는 CSV가 기준이고 코드와 테스트는 CSV만 읽는다. PLAN 본문의 표는 2026-10-18 시점의 기록으로 남기고 고치지 않으며, 둘이 다르면 CSV가 맞다.
   - 파일 이름(가안): `admin_changes.csv`, `provider_urls.csv`, `published_totals.csv`. 섬 링크·연륙·연도교·도로 등급 라벨·검증용 도시 쌍(`island_links.csv`, `bridges.csv`, `road_rank_labels.csv`, `sanity_pairs.csv`)도 같은 폴더에 둔다(G23). 열 구성, 출처, 확인일은 `configs/reference/README.md`에 적는다.
   - 모든 파일을 `sources`에 해시와 함께 등록한다. 줄바꿈은 LF로 고정되어 있고(`.gitattributes`), 해시는 LF로 정규화한 내용으로 구한다(ADR 0006).
   - OSM에서 파생된 파일(`bridges.csv`, `island_links.csv`의 좌표)을 옮길 때는 NOTICE.md를 갱신한다(CLAUDE.md 규칙).
   - 옮기면서 PLAN 본문과 값이 달라지면 이유를 커밋 메시지에 적는다.
