# 0014-전력망 탐색 실험

- 상태: 제안(실행 2026-10-20, 커밋 c8de6c2. 사후 채택 대기)
- 날짜: 2026-10-20(제안과 실행), 2026-10-20(검토 반영 수정: 상태, 2·5항, 4항의 공개 범위 참조, 영향, 열린 점)
- 관련: PLAN G8, G27, 6.1a(0S 선례), 6.8절, 9장 / ADR 0001(5항), 0012, 0013 / DESIGN 3장

## 배경
ADR 0012가 `layer = power` 스키마와 7단계(M7, v1 이후 백로그)의 방향을 정했지만, 자료원과 보안 검토 기준은 열린 점으로 남았다. 계산 단계로 가기 전에 OSM `power` 태그만으로 송전 그래프를 어디까지 만들 수 있는지, 구조 지표(브리지, 유효 저항)가 무엇을 보여 주는지를 작게 확인하려 한다. 0S에서 곡률 해석이 엣지 길이의 의미에 달려 있다는 점을 배웠으므로, 엣지 가중치의 의미를 먼저 적어 둔다.

## 선택지
7단계 착수 때까지 미룬다 / 7단계 백로그 중 작은 탐색만 한 세션으로 앞당긴다. 후자를 택한다.

## 결정
1. 목적: 7단계 백로그 중 "OSM으로 송전 그래프를 만들 수 있는가"와 "구조 지표가 무엇을 보여 주는가"만 앞당겨 본다. v1 범위와 PLAN 6.8·9장 일정은 바꾸지 않는다.
2. 범위와 시간 상한: 2026-10-20 한 세션(커밋 c8de6c2). 못 끝낸 항목은 미완으로 두고 기한을 늘리지 않는다.
3. 자료: OSM `power` 태그(Geofabrik south-korea-261017, ODbL)만 쓴다. 계통 운영·수급 자료와 DC 조류·PTDF는 쓰지 않는다(PLAN 6.8: 이후 단계).
4. 규칙: 탐색적이며 사전 판정 규칙이 없다. 합격·불합격을 정하지 않고, 결과를 다른 결정의 근거로 인용하지 않는다. 결과물(표·그림·그래프)은 저장소 밖 `C:\dev\kfm-data\power\`에만 두고, 저장소에는 코드(`notebooks/spike/power/power_lib.py`)와 출력을 지운 노트북(`05_power_grid.ipynb`)만 둔다. 공개 전에는 PLAN 6.8의 보안 검토를 거친다(공개의 범위는 열린 점이다). 개별 선로·변전소 단위 결과는 인용하지 않고 집계만 쓴다.
5. 관계: ADR 0012의 `layer = power` 스키마(`network_nodes`, `network_edges`, `network_edges_power`의 voltage_kv·reactance, `layer_coupling`의 `located_in`)에 담기는지 모양만 확인하고, 스키마·설정·`kfm` 패키지·`runs`는 바꾸지 않는다(탐색 코드는 PLAN 6.1a의 0S 선례처럼 규칙 밖에 둔다). 리액턴스는 길이 / 전압²에 비례하는 대용값이며, DC 조류(PLAN 6.8)는 이후 단계다. HVDC(제주)는 ADR 0012 5항대로 서셉턴스 선로가 아니므로 AC 그래프에서 뺀다. 예외는 `kfm` 패키지·`runs`·스키마 검증·테스트 규칙에만 적용하고, `data/raw/` 불변과 좌표계·단위 규약은 지킨다(ADR 0001 5항). 노트북 앞부분에 자료 파일명·해시·패키지·가정값을 적고, 끝에는 `power_run_meta.json`(설정 해시, 자료 스냅숏, 코드 버전, 시드)을 남긴다.
6. 0S의 교훈: 곡률 해석은 엣지 길이의 의미에 달려 있다(ADR 0013 배경 (4), 0S 보고서). 이 탐색은 곡률을 계산하지 않는다. 후속에서 전력망에 곡률을 쓰려면 엣지 길이의 의미(km, 리액턴스 대용값, hop)를 먼저 고정하고, 길이 정의에 따라 해석이 달라짐을 전제한다.

## 열린 점
- 보안 검토의 주체와 기준(ADR 0012의 열린 점을 이어받는다). 검토 전에는 어떤 결과도 공개하지 않는다.
- '공개'의 범위(사용자 결정). 4항은 집계만 인용한다고 하지만, 비공개 저장소 문서(`docs/IMPLEMENTATION.md` 진행 현황의 노드·엣지 수와 최대 성분 비율)에 적은 집계가 '공개'에 드는지는 정해져 있지 않다. NOTICE.md는 저장소의 OSM 파생 파일을 ODbL 1.0으로 공개한다고 적어 저장소 공개를 전제한다. 저장소를 공개로 바꾸면 그 순간 보안 검토 전 공개가 된다. 두 안이 있다.
  - 안 A: 저장소 문서에는 전국 합계 수준의 집계(노드·엣지 수, 성분 비율)만 적을 수 있다. 저장소를 공개로 바꾸기 전에 이 집계도 보안 검토에 넣는다.
  - 안 B: 저장소에는 집계도 적지 않는다. 이 경우 진행 현황 행을 '완료(탐색). 결과는 저장소 밖 `C:\dev\kfm-data\power\`(비공개)'로 줄이고, 아래 N-1 기준과 스키마 모양 확인 항목의 결과 서술은 '7단계에서 N-1 기준(구간/회선)과 확장 테이블 열을 정한다'로 바꾼다.
- 4항 인용 규칙 개정(사용자 결정). 아래 OSM 완결성·N-1 기준·스키마 모양 확인 항목이 결과(태그 결측, 구간·회선 브리지 비율 차이, 열 부족)를 7단계 결정의 동기로 적어 4항("결과를 다른 결정의 근거로 인용하지 않는다")과 긴장 관계다. 안: 결과는 7단계 계획(자료원 선택, N-1 기준, 확장 테이블 명세)의 참고로만 쓰고 채택 결정의 단독 근거로 인용하지 않는다. 이 안을 채택하지 않으면 그 항목들의 결과 서술을 줄인다.
- OSM 완결성 한계(지중 케이블 누락, 전압·회선 태그 결측)를 7단계 자료원 선택에 어떻게 반영할지.
- N-1 기준: 구간(회랑) 단위와 회선 단위의 브리지 비율이 크게 다르다. 7단계에서 N-1 기준을 정할 때 함께 정한다.
- 스키마 모양 확인에서 `network_edges_power`에 회선 수·지중 여부·HVDC 구분 열이 더 필요해 보였다. 7단계에서 층별 확장 테이블 명세를 정할 때 다룬다.
