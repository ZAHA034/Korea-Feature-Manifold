# 0003-공간 단위, 경계 기준 시점, 비교 시점, 좌표계 예외

- 상태: 제안 (0단계에서 확정)
- 날짜: 2026-10-20
- 관련: PLAN 4.1 질문 1·2, G21, G25(비교 시점 선택), 6.2절 / DESIGN 4.1, 13 / ADR 0002·0004

## 배경
DESIGN 13의 열린 질문(기준 공간 단위와 확장 시점, 기준 연도)과 H3 색인이 "계산은 EPSG:5179" 규약과 충돌하는 문제(G21)가 남아 있다. 2026년에 화성 일반구 설치, 인천 개편, 전남광주 통합이 시행되어 2025년 경계와 달라졌다. 변화율(λ2)의 비교 시점 선택은 ADR 0004가 이 ADR에 넘겼다.

## 선택지
기준 단위는 시군구로 시작 / 읍면동으로 시작. 경계 기준은 2025-12-31 / 2026년 개편 반영. 비교 시점은 2015 / 2020. H3 색인용 좌표는 5179로 변환 / 4326 예외.

## 결정
1. 기준 공간 단위는 통계용 시군구다(일반구, 제주 행정시, 세종 포함. 2025-12-31 기준 252개). 읍면동은 3단계가 시군구에서 검증된 뒤 분석 단위로 더하고(MAUP 교차 확인) 5단계 보고서 전에는 반드시 더한다. 읍면동 자료 자체는 1단계에서 수집한다(대응표의 행정동 재집계에 필요하다). 읍면동은 행정동 기준이다. 주민등록 인구, 경계 자료, 대응표 재집계가 모두 행정동 단위이기 때문이다. H3는 4단계 적응 세분화에서만 쓴다.
2. `regions.unit` 값은 `sido`, `sigungu`, `si`, `emd`, `h3_r{n}`이다. `si`는 일반구를 둔 시(2025-12-31 기준 12곳)의 집계용 행이고 그 일반구 35개의 `parent_id`다. 자치 시군구 단위 결과는 `si`와 일반구가 없는 `sigungu`로 구성한다. 국내인구이동의 229개 단위가 이 구성이다(`sigungu` 217개와 `si` 12개).
3. 경계 기준 시점은 `base_2025`(2025-12-31 경계)로 고정한다. `base_YYYY`는 YYYY-12-31에 유효한 `regions` 상태 전체다(`valid_from` ≤ 그날 < `valid_to`. ADR 0002). 속성은 2025년 기준이다. 2026년 개편(화성 일반구 4개, 인천 중구·동구·서구 개편, 전남광주 통합)은 기준선에 반영하지 않고 대응표 검증 사례로 쓴다. 새 기준 시점은 ADR로 정한다.
4. 비교 시점(G25)은 2020년이다. 주민등록 2020-12(월말)를 쓰고, 등록센서스를 쓰면 2020-11-01과 2025-11-01을 짝으로 쓰며 한 지표 안에서 두 출처를 섞지 않는다. 2015는 행정동을 나누는 변경(2018 전주, 2019 수원–용인)이 있어 정확히 옮겨지지 않으므로 v1에서 뺀다. 2020 값은 ADR 0004에 따라 `base_2025` 경계로 옮긴다.
5. OD의 기준연도는 확보할 수 있는 최신 연도를 쓰되, 연도 차이를 `runs.data_snapshot`과 보고서에 남긴다. OD 구조를 쓰는 계산의 단위(KTDB 250, 인구총조사 통근·통학 249, 국내인구이동 229)는 기준 단위(252)와 다르며 ADR 0004 7항을 따른다.
6. 좌표계 예외(G21): 저장·계산은 EPSG:5179, 웹 표시는 EPSG:4326이다. H3 색인을 만들 때만 EPSG:4326을 쓰고 저장 geometry는 5179로 둔다. 변환은 pyproj `always_xy=True`로 한다(DuckDB `ST_Transform`은 `always_xy` 없이 경위도를 넣으면 `inf`를 돌려준다).

- CLAUDE.md 규약: 좌표계 항에 "H3 색인을 만들 때만 EPSG:4326을 쓰고 저장은 5179"를 더한다(PLAN 11.1)

## 열린 점
- 세종(시도이면서 시군구)과 제주 행정시의 계층 표현. 세종은 `sido` 행과 `sigungu` 행을 모두 두는 안을 1단계에서 확인한다
- `si` 행에 geometry를 저장할지(일반구의 합집합) 필요할 때 계산할지
