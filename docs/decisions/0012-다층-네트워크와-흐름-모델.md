# 0012-다층 네트워크와 흐름 모델

- 상태: 제안. 1–3항(스키마)과 4항의 설정 키·값 목록은 0단계에서 확정한다. 4항의 흐름 모델별 계산 방식과 5항(전력망)은 M7 착수 전에 확정한다
- 날짜: 2026-10-18(제안), 2026-10-20(검토 반영 수정: 영향에 PLAN 변경 이력 줄 추가)
- 관련: PLAN G8, G27, 5.3절 (가), 6.1절 0-2·0-4·0-5, 6.8절 / DESIGN 3장, 4.2, 9.1, 12

## 배경
DESIGN 3장의 연결층은 도로·철도망만 전제한다. 나중에 전력·가스·수도·하천·통신망을 넣으려면 지금 스키마가 층을 구분해야 한다. 층마다 흐름의 물리도 다르다. 도로에서는 이용자가 경로를 고르고, 전력은 퍼텐셜 차로 흐르며, 하천은 지형을 따라 흐른다. 구현은 v1 이후로 두되, 스키마는 지금 정해 나중의 이전 비용을 없앤다.

## 선택지
층마다 별도 테이블을 두는 방식과, 공통 테이블에 `layer` 컬럼을 두고 층별 속성만 확장 테이블로 분리하는 방식 중에서 고른다.

## 결정
1. `network_nodes`(node_id, layer, geometry, source_id)와 `network_edges`(edge_id, layer, from_node, to_node, directed, length_km, geometry, source_id)에는 공통 컬럼만 둔다. `layer` 값은 road, rail, power, gas, water, river, telecom이다.
2. 층별 속성은 확장 테이블 `network_edges_{layer}`(필요하면 `network_nodes_{layer}`)로 분리한다. 예: road는 road_rank, lanes, max_speed, oneway, observed_volume이고, power는 voltage_kv, reactance, capacity_mw다. observed_volume(DESIGN 4.2의 구간 교통량)은 조사 지점 자료를 링크에 매칭한 결과라서, 매칭 방법과 함께 3단계 이후에 채운다. v1에서 채우는 층은 road뿐이다.
3. `layer_coupling`(coupling_id, src_layer, src_node_id, dst_kind = region / node, dst_layer, dst_id, relation, weight, valid_from, valid_to, source_id)으로 노드 ↔ 지역, 층 ↔ 층 관계를 둔다. `relation` 값은 다음과 같다.
   - `located_in`: 노드의 소재 지역. 도로 노드의 지역 귀속도 이것으로 둔다
   - `serves`: 서비스 지역(예: 변전소 → 시군구)
   - `depends_on`: 층 간 의존(예: 정수장 → 전력 노드)
4. 층별 흐름 모델은 설정 `layers.<layer>.flow_model`로 정한다.
   - `choice`(선택형): 최단경로·통행 배정. 도로, 철도
   - `potential_linear`(퍼텐셜형): DC 조류. 전력
   - `potential_nonlinear`(퍼텐셜형): 비선형 관망 수리. 가스, 물
   - `gravity_tree`(중력형 방향 트리): DEM 흐름 방향. 하천
   - `information`(정보형): 통신

   설정 키와 값 목록은 0단계 설정 모델에 넣는다(PLAN 0-4). v1은 `choice`만 구현하고, 나머지 값은 "미구현" 오류를 낸다.
5. 전력망 방향(구현은 3단계 검증 이후):
   - DC 조류는 서셉턴스로 가중한 라플라시안 B에 대해 θ = B⁺P로 풀고, 선로 조류는 f_ij = b_ij(θ_i − θ_j)다. DESIGN 6.5의 통근 시간 거리(= vol(G)·유효 저항)와 같은 L⁺ 도구이므로, PLAN 3-6의 유효 저항 함수(vol(G) 배율 없음)를 다시 쓴다.
   - 지역별 (발전량 − 소비량)을 불균형 밀도장 P로 둔다. θ = B⁺P는 연결 성분마다 ΣP = 0일 때만 쓴다. P는 같은 시점의 전력(MW) 스냅숏이며, 손실·자체소비로 생기는 불균형은 명시한 slack 규칙(단일 slack 또는 비례 분산)으로 맞춘다. B⁺로 구한 단일 모선 PTDF에도 slack 규약을 적는다.
   - N-1에서는 선로 k를 끊기 전에 섬이 생기는지(b_k·R_eff(k) = 1) 검사하고, 섬이 생기면 섬별 수급 규칙(부하 차단, 발전 조정)을 적용한 뒤 푼다.
   - b_ij는 공통 MVA 기준의 p.u. 서셉턴스(1/x_pu)로 둔다. HVDC 연계(제주)는 서셉턴스 선로가 아니라 제어 주입으로 모델링한다.
   - 분석 항목은 송전 분배 계수(PTDF), 음곡률 선로, N-1 회복력(PLAN 3-6의 엣지 제거 함수)이다.
   - 상세 계통은 공개가 제한적이므로 시도·권역 단위 등가 계통에서 시작한다. 결과물 공개 범위는 `sources.license`와 별도 보안 검토로 제한한다.
   - 시나리오 연산자 후보(v1.x)는 `add_line`, `remove_line`, `add_generator`, `shift_demand`다.
6. 일정은 PLAN 9장 M7(선행 M3)에 백로그로 둔다.
